# Contributing to SpreadSignal

Thanks for helping make outbreak intelligence clearer and more responsible.

## Before you start

- Review the [README](README.md) and existing issues before proposing a change.
- Keep the prototype’s core promise intact: observations need context, analysis is exploratory, and preparedness actions stay under human review.
- Do not add live health data, credentials, or personally identifiable information to the repository.

## Reporting a bug

Use the bug-report form and include reproducible steps, the expected result, the actual result, and relevant browser or device details. Please do not include sensitive information.

## Suggesting an improvement

Use the feature-request form. Explain the problem, who it helps, and how the proposed change preserves the project’s evidence-first approach.

## Making a change

1. Create a focused branch from `main`.
2. Make a small, reviewable change.
3. Check the static app locally with `python3 -m http.server 8000`.
4. Verify responsive behavior and the synthetic-data notices where relevant.
5. Open a pull request using the provided template.

## Design and content principles

- Use clear, plain language; avoid alarmist framing.
- Keep source, method, coverage, and limitation context close to observations.
- Clearly distinguish illustrative prototype data from live surveillance data.
- Preserve accessibility: semantic markup, readable contrast, and keyboard-friendly controls.

By contributing, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
